# 暖迹地图技术说明

地图是本地优先的私人数据模型。`MapCollection` 保存地图元数据，`PlaceRecord` 保存地点状态、日期、照片、心情、备注、来源和可选坐标。地点可以没有坐标，仍能作为待定位记录保存和编辑。

客户端通过 `MapProviderAdapter` 管理底图、Marker、聚合、视野和选中状态；`MapView` 同时提供可访问的列表入口。用户拖动地图只更新本地视野，只有点击“搜索此区域”才发起 POI 请求。视野内统计和全部地点统计分别展示。高密度点位使用聚合，地图不可用时列表和编辑保持可用。

高德 JS API 只接收客户端标识，Web 服务密钥、AI 密钥和天气请求由 Fastify 服务端持有。高德 POI 坐标标记为 `GCJ02`；设备定位是 `WGS84`，必须通过高德转换接口后才可用于底图。系统不会把 WGS84 数值直接当作 GCJ-02 使用。

POI 搜索使用高德 POI 2.0 `/v5/place/text`、`/v5/place/around` 和 `/v5/place/detail`。地理编码、逆地理编码和实时天气使用对应的 v3 服务。所有响应同时检查 HTTP 状态、`status`、`info`、`infocode`、空数组与坐标格式；HTTP 200 不会被直接当成业务成功。

`AMAP_WEB_SERVICE_KEY` 只用于服务端 POI、地理编码和天气。它不能替代浏览器高德底图所需的 `AMAP_JS_KEY`。交互底图还要求配套 `AMAP_SECURITY_CODE`；JS Key 是受来源限制的公开标识，安全密钥只保留在服务端签名代理中。

天气按目标城市解析 adcode，并返回天气内容、`reporttime`、`fetchedAt` 和缓存状态。服务端保存十分钟新鲜缓存，客户端只持久化不含备注和坐标的天气摘要；断网时可以显示明确标注的缓存或过期缓存，不能显示伪造天气。

分享卡片默认只带标题、状态、地点名和城市摘要。精确坐标、照片、私人备注和收礼人信息需要逐项开启；完整 ZIP 备份单独提供并明确包含敏感字段。

“AI 暖迹灵感”只把用户主动输入的描述转换成关键词、类别、城市和半径。客户端再调用真实 POI 搜索，模型不能直接创建地点、商家或坐标。足迹故事只读取用户选中地图的地点名称、状态、心情和经授权备注，生成结果先进入可编辑预览，用户确认后才更新地图介绍。照片和精确坐标默认不上传。
